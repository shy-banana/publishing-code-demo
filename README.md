# 香蕉攀岩发布平台 Demo

供同事练习从 GitHub 代码发布应用、保存测试记录，以及更新和恢复程序版本。仓库由 [shy-banana](https://github.com/shy-banana) 维护。

## 同事怎么使用

1. Fork 本仓库到自己的 GitHub 账号，或克隆后推送到自己的新仓库。
2. 打开 [公司发布平台](https://publish.bananaclimbing.top/)，用本人企微登录，连接本人的 GitHub，并向平台开放刚创建的仓库。
3. 新建代码应用，选择自己的仓库、`main` 分支和实际提交，检查后发布。
4. 打开返回的应用地址，填写一条测试记录，刷新后确认仍在。修改自己仓库的页面文案，发布新提交后再次检查记录。
5. 需要练习程序版本恢复时，选择本应用已经成功发布的历史版本，并确认该版本与当前数据库兼容。

发布平台准备应用数据库、证书及登录网关。环境配置由平台注入。每个新应用使用自己的数据资源。

## 选择分支

| 分支 | 用途与数据范围 |
| --- | --- |
| `main` | 简单发布验收。通过本应用登录准入的人共享查看和新增验收记录 |
| `codex/menu-permission-acceptance` | 双菜单权限验收。每个人仅查询、登记和汇总本人记录，依赖平台菜单策略及网关注入身份 |
| `archive/origin/*` | 历史发布实验，涵盖 TypeScript、Python、Java、静态页面等。按各分支自己的依赖和运行要求使用 |
| `archive/origin/validation-failure` | 故意构建失败的恢复演练，用来验证已有应用在失败后的状态 |

菜单权限分支用于新建独立测试应用。已有主分支数据的应用切换到该分支前，需要评审 `created_by` 字段和历史记录归属，执行相应数据库升级。

主分支用于测试内容。正式业务需要自行定义业务角色、门店及记录权限。需要个人记录隔离时使用菜单权限分支，或使用 [标准应用模板](https://github.com/shy-banana/internal-app-template)。

## 运行与发布要求

- Node.js 22.12.0 或以上，pnpm 11.25.0，按 `pnpm-lock.yaml` 安装。
- 启动命令 `pnpm start`，默认端口 3000，就绪检查 `/readyz`。
- PostgreSQL 使用 `DATABASE_URL`，CA证书文件由 `PG_CA_CERT_PATH` 指定，连接验证 TLS。
- `database/001-initial.sql` 是新应用的初始化结构。已有业务库的升级须走平台数据库升级流程。
- `nativeOidc:false` 表示由发布平台登录网关处理员工身份。正式运行须让应用程序位于网关后的受控网络。

单独在本地执行 `pnpm start` 前，需要自行准备隔离数据库、建表及证书。主分支的应用程序依赖平台网关执行登录准入。

```sh
pnpm install --frozen-lockfile
pnpm start
```

## 源码维护权限

本仓库公开读取，原仓库写入和合并由所有者维护。同事在自己的 Fork 中修改、提交和发布自己的应用，也可以提交 Pull Request 供所有者审阅。

## 兼容性核对

2026-11-16，主分支与菜单权限分支已通过公司发布平台的源码兼容检查。主分支依赖已按锁文件安装，并在本地 Node.js 24.22.1 和隔离 TLS PostgreSQL 中验证首页、保存、筛选、非法标题拒绝、版本读取及应用重启后记录保留。菜单权限分支的6项真实 HTTP／PostgreSQL 检查通过，覆盖本人数据范围、全公司准入、伪造范围拒绝及撤权。历史实验分支按其原有环境要求保留，各分支的验证范围需要分别核对。

仓库源码的公开访问权限与部署后应用的使用权限分别配置。应用内员工准入由发布平台及其业务规则执行。
